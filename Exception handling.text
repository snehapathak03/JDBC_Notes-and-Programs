Chapter 1: Introduction to Exception Handling

What is Exception Handling?Imagine you're writing a Java program.Everything is working perfectly until suddenly:User enters 
a letter instead of a number.File you're trying to read doesn't exist.Database connection fails.Internet connection drops.
Memory becomes full.Should the program immediately stop?If yes,the user loses everything.Instead,Java provides Exception 
Handling, which allows the program to detect, report, and (where appropriate) recover from unexpected problems.
Definition:Exception Handling is a mechanism in Java for detecting, handling, and recovering from runtime problems so that 
the normal flow of the program can continue whenever possible.It separates normal business logic from error-handling logic, 
making programs more robust and easier to maintain.

Why Do We Need Exception Handling?Suppose you write this program:
public class Demo {
    public static void main(String[] args) {
        int a = 10;
        int b = 0;
        int c = a / b;
        System.out.println(c);
        System.out.println("Program End");
    }
}
Output:Exception in thread "main" java.lang.ArithmeticException: / by zero
Notice that:System.out.println("Program End"); never executes.The JVM immediately terminates the program because the 
exception was not handled.Without Exception Handling
Program Starts
      │
      ▼
Execute Statement
      │
      ▼
Exception Occurs
      │
      ▼
Program Terminates

BUT With Exception Handling:
Program Starts
      │
      ▼
Execute Statement
      │
      ▼
Exception Occurs
      │
      ▼
Catch Exception
      │
      ▼
Continue Program
This is the fundamental purpose of exception handling.Real-Life Example:Imagine you're driving a car.Without brakes:
Obstacle
↓
Accident
↓
Journey Ends

With brakes:
Obstacle
↓
Brake Applied
↓
Avoid Accident
↓
Journey Continues
Exception Handling acts like the braking system of a program.It doesn't prevent every problem from occurring, 
but it gives your program a controlled way to respond.

Another Real-Life Example is Suppose you're using an ATM.
Scenario:You insert your ATM card.Enter the PIN.Request ₹5,000.But the ATM has no cash.
Without exception handling:ATM Crashes and/or Screen Turns Off.With exception handling:Sorry!Insufficient Cash.
Please try another ATM.The application continues to work gracefully.

What Exactly is an Exception?An exception is an object that represents an abnormal condition occurring during the 
execution of a program.Many beginners think an exception is just an error message.That's incorrect.An exception is an object.
When something goes wrong, Java creates an object containing information about the problem.For example:int a = 10;int b = 0;
System.out.println(a / b);
Java internally creates an object similar to:ArithmeticException exception = new ArithmeticException("/ by zero");
This object stores details such as:Exception type,Error message,Location of the error,Call stack.

Life Cycle of an Exception:Whenever an exception occurs, Java follows a sequence.
Statement Executes
↓
Problem Occurs
↓
JVM Creates Exception Object
↓
JVM Searches for Handler
↓
Found?
├── YES → Handle Exception → Continue
└── NO → Program Terminates
This sequence is one of the most commonly asked interview topics.

Who Creates Exception Objects?There are two possibilities.
1. JVM Creates It
Example:int x = 10 / 0;The JVM automatically creates:ArithmeticException
2. Programmer Creates It:Using the throw keyword:throw new ArithmeticException("Invalid Input");

Where Can Exceptions Occur?Almost anywhere.Examples include:
Arithmetic:int x = 10 / 0;

Array:int[] arr = new int[5];
System.out.println(arr[10]);

String:String s = null;
System.out.println(s.length());

File:FileReader reader =new FileReader("abc.txt");
If abc.txt doesn't exist, an exception occurs.

Database:Connection con =DriverManager.getConnection(...);
If the database server is unavailable or credentials are wrong, an exception is thrown.

What Happens Without Exception Handling?
public class Test {
    public static void main(String[] args) {
        System.out.println("Start");
        int a = 10 / 0;
        System.out.println("End");
    }
}
Output
Start
Exception in thread "main"
ArithmeticException
Notice:End    never executes.

What Happens With Exception Handling?
public class Test {
    public static void main(String[] args) {
        System.out.println("Start");
        try {
            int a = 10 / 0;
        } catch (ArithmeticException e) {
            System.out.println("Cannot divide by zero");
        }
        System.out.println("End");
    }
}
Output:Start
Cannot divide by zero
End
Now the program continues after handling the exception.

Advantages of Exception Handling
1. Prevents Abnormal Termination:Programs don't have to stop immediately when something unexpected happens.
2. Improves User Experience:Instead of:Program Crashed You can display:Please enter a valid number.
3. Improves Maintainability:Error-handling code is separated from business logic, making programs easier to read and update.
4. Makes Debugging Easier:Exceptions include:Exception type,Message,Stack trace
These details help developers locate and fix problems quickly.
5. Improves Reliability:Applications become more stable because they can respond to common failures gracefully.

Where Is Exception Handling Used?It's used in almost every Java application:Banking software,ATM systems,Hospital management 
systems,E-commerce websites,Railway reservation systems,Spring Boot REST APIs,JDBC applications,Android apps,Desktop 
applications and Cloud services.Whenever an operation can fail, exception handling is relevant.
Common Misconceptions:
❌ "Exceptions are compile-time errors."->No. Most exceptions occur during program execution (runtime).
❌ "Exception and Error are the same."->No.Errors and exceptions are different concepts.
❌ "Exception handling prevents exceptions."No.It handles exceptions after they occur; it doesn't prevent them from happening.

Interview Questions
1. What is Exception Handling?A mechanism in Java used to detect, handle, and recover from runtime problems so that the 
application can continue running whenever appropriate.
2. Why do we need Exception Handling?To prevent abrupt program termination, improve reliability, separate error-handling 
logic from business logic, and provide meaningful feedback to users.
3. Is an exception an object?Yes.Every exception in Java is an object derived from the Throwable class.
4. Who creates exception objects?The JVM creates many built-in exception objects automatically.A programmer can create 
and throw exception objects using the throw keyword.
5. Does every exception terminate the program?No.If an exception is caught by a suitable catch block, the program can 
continue executing.

Key Takeaways
Exception Handling manages unexpected runtime problems.
Exceptions are objects, not just messages.
The JVM creates exception objects for many runtime failures.
If an exception is not handled, the JVM terminates the program.
try and catch blocks allow programs to recover from many exceptions.
Exception handling improves robustness, maintainability, and user experience.

1. Introduction:In the previous chapter, we learned that an exception is an object.Now the question is:Where do these

2. What is Throwable?Throwable is the root class of Java's exception handling mechanism.Every object that can be thrown 
using the throw keyword or by the JVM must inherit from Throwable.
Definition:Throwable is the superclass of all Errors and Exceptions in Java.Package:java.lang.Throwable
Since java.lang is imported automatically, you don't need to import it explicitly.

3. Why Did Java Introduce Throwable?Suppose Java had no common parent class.ArithmeticException,IOException,NullPointerException,
StackOverflowError.Each would be unrelated.It would be impossible to write generic code like:catch(Throwable t)
The Throwable class provides a common type for all problems.

21. Interview Questions
Q1. What is Throwable?
Answer:Throwable is the root class of Java's exception hierarchy. All exceptions and errors inherit from it.

Q2. What is the difference between Error and Exception?
Answer:Errors indicate serious JVM-level problems that are usually unrecoverable, whereas exceptions represent 
application-level problems that can often be handled.

Q3. Can we catch an Error?
Answer:Yes, it is technically possible because Error extends Throwable. However, it is generally discouraged 
because errors usually indicate unrecoverable conditions.

Q4. Why do all exceptions inherit from Throwable?
Answer:This provides a common parent class, enabling generic exception handling and allowing the JVM to throw 
any problem object consistently.

Q5. What information does an exception object contain?
Answer:An exception object typically contains:Exception type,Error message,Stack trace,Cause,Suppressed exceptions (if any).

Common Mistakes
Confusing Errors with Exceptions.
Assuming every exception is checked.
Catching Throwable or Error indiscriminately in application code.
Ignoring stack traces when debugging.

Best Practices
Catch the most specific exception possible.
Do not catch Throwable unless you have a very specialized framework-level reason.
Avoid catching Error in normal application code.
Use printStackTrace() or, preferably in production applications, a logging framework to record exception details.

Summary
Throwable is the root class of Java's exception mechanism.
It has two major subclasses: Error and Exception.
Errors are serious JVM-related issues and are generally unrecoverable.
Exceptions are application-level problems that can often be handled.
RuntimeException represents unchecked exceptions.
Other subclasses of Exception (such as IOException) are typically checked exceptions.
Exception objects carry useful debugging information like messages and stack traces.

Chapter 3: Checked vs Unchecked Exceptions — Complete Deep Dive
1. First Understand the Big Picture
We already learned:
Object
   │
   ▼
Throwable
   │
   ├────────────── Error
   │
   └────────────── Exception
                    │
                    ├────────────── RuntimeException
                    │
                    └────────────── Other Exceptions

Now Exception is broadly divided into:

                    Exception
                       │
             ┌─────────┴─────────┐
             │                   │
       Checked Exception    RuntimeException
                                  │
                           Unchecked Exception

So we have:
Checked Exceptions:Compiler checks them.
Unchecked Exceptions:Compiler does not force you to handle them.

2. What is a Checked Exception?
A checked exception is an exception that the Java compiler requires you to either:Handle using try-catch,
 or Declare using throws. They are checked at compile time.
Example:
import java.io.FileReader;
public class Demo {
    public static void main(String[] args) {
        FileReader file =
                new FileReader("student.txt");
    }
}
This gives a compilation error similar to:Unhandled exception type FileNotFoundException.Why?Because FileNotFoundException 
is a checked exception.

3. Why Does the Compiler Check It?
Imagine you're writing:FileReader file = new FileReader("student.txt");
There is a genuine possibility that:student.txt doesn't exist.
Java designers want you to explicitly decide:"What should my program do if the file doesn't exist?"
So the compiler forces you to handle or declare the exception.

4. Two Ways to Handle a Checked Exception
Method 1: try-catch
import java.io.FileReader;
import java.io.FileNotFoundException;
public class Demo {
    public static void main(String[] args) {
        try {
            FileReader file = new FileReader("student.txt");
        } catch (FileNotFoundException e) {
            System.out.println(
                "File not found"
            );
        }
    }
}

5. Method 2: throws
Instead of handling the exception, you can pass responsibility to the caller.
import java.io.FileReader;
import java.io.FileNotFoundException;
public class Demo {
    static void readFile()
            throws FileNotFoundException {
        FileReader file = new FileReader("student.txt");
    }
    public static void main(String[] args)
            throws FileNotFoundException {
        readFile();
    }
}
We'll study throws deeply in a later chapter.
For now remember:
Checked Exception
        │
        ├── try-catch
        │
        └── throws

8. What is an Unchecked Exception?
An unchecked exception is an exception that the compiler does not require you to catch or declare.
They are primarily represented by subclasses of:RuntimeException

9. Example of Unchecked Exception

    }

Does the compiler complain?No.The program compiles.
When you run it:ArithmeticException occurs.

10. Why Isn't the Compiler Checking This?
Because the compiler cannot reasonably force you to handle every possible programming mistake.
For example:
String name = null;
name.length();
This is generally a programming logic problem.
The compiler cannot determine whether name will actually be null at runtime.
Therefore:
Compile Time
      ↓
No Error
Run Time
      ↓
NullPointerException

25. Why Does Java Have Checked Exceptions?
This is a very important conceptual interview question.
Java's checked exceptions provide compile-time enforcement for failures that a caller may reasonably be expected to anticipate and handle.
For example:new FileReader("data.txt");
A file may legitimately be absent.Therefore Java forces you to address that possibility.

26. Why Are Runtime Exceptions Unchecked?
Runtime exceptions frequently indicate programming defects or invalid assumptions.
Example:
String name = null;
name.length();
The appropriate fix is often:Fix the program logic
rather than:Catch NullPointerException everywhere

So saying simply:"Exception is checked"

Correct explanation:

   ├── RuntimeException → Unchecked
