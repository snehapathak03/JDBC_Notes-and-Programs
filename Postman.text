EXTRA:
1. What is Postman?Postman is an API Development and Testing Tool used by developers to create, test, debug, document, 
    and automate REST APIs without writing frontend code.It allows developers to send HTTP requests directly to a server 
    and inspect the responses.Instead of creating an HTML page or mobile application just to test an API, Postman lets you 
    send requests directly.Real-Life Example:Imagine a restaurant.Customer → Waiter → Kitchen
    Normally
    Customer = Browser
    Waiter = HTTP
    Kitchen = Server
    With Postman,
    You become the waiter.
    You directly send requests to the kitchen without needing a restaurant dining experience.
    Browser
       ↓
    Server
    OR
    Postman
       ↓
    Server

2 Why Do We Need Postman?Suppose you build this API:GET /students
Without Postman,You would need to:Create HTML,Write JavaScript,Connect Backend and then Display Data.
That is unnecessary when you only want to test the API.
With Postman:Click Send -->Receive Response
Advantages:
i.Fast API Testing
ii.No Frontend Required
iii.Supports All HTTP Methods
iv.Authentication Support
v.Easy Debugging
vi.Automation
vii.API Documentation
viii.Team Collaboration

3 History of Postman:Created in 2012 by Abhinav Asthana, Ankit Sobti, and Abhijit Kane.
Initially developed as a Chrome extension.Later became a full desktop application.
Today it is one of the most widely used API testing tools.

23 Tests (Assertions)
After a request, you can validate the response automatically.
Example:
pm.test("Status is 200", function () {
    pm.response.to.have.status(200);
});

Another example:
pm.test("Response is JSON", function () {
    pm.response.to.be.json;
});
These tests help ensure your API behaves as expected.

28 Postman vs Browser
Browser	Postman
Designed for websites	Designed for APIs
Limited control	Full control over requests
Difficult to test APIs	Easy API testing
Limited request customization	Complete request customization
No automated API tests	Supports automated tests

29 Postman vs Swagger
Postman	Swagger/OpenAPI
API Testing	API Documentation
Manual & automated requests	API specification
Collections	Interactive documentation
Environment support	API design-first approach

Many teams use both together:
Swagger to document APIs.
Postman to test them.

30 Best Practices
Organize requests into collections.
Use environment variables instead of hardcoding URLs.
Name requests clearly (e.g., GET Students, Create Student).
Validate responses with tests.
Secure secrets (API keys, tokens) using variables.
Reuse common headers and authentication at the collection level.
Keep collections version-controlled (e.g., Git).
